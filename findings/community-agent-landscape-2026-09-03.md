# Who else is doing persistent agents, agent teams, or org-level Omarchy

Status: research note, 2026-09-03, afternoon. Sources: the Omacom Discord (server search, read through the web app: swarm, "multiple agents", orchestration, persistent, "persistent agent", openclaw, fleet, enterprise, "multiple users", worktree, ralph), GitHub Discussions and Issues on `omacom/omarchy`, the marketplace repository, `plugins.omarchy.org`, `omarchyplugins.com`, and web search. The GitHub half was gathered by a subagent that opened each page it cites; items marked *snippet* come from a search result it did not open. Nothing was posted or replied to during the sweep.

## The result

Nobody in the Omarchy community is building a durable session object with receipts, and nobody is coordinating a team of agents on one goal from the desktop. The nearest things are resume tools (Session Browser, Hermes Sessions), monitors (Agent Orchestrator, the Herdr bar plugin), and worktree-per-agent launchers (Maestro, `tsl`, agentic-dev-setup, qj-orch, `preview`). The demand is there in the chat: people ask how to run an agent somewhere it survives and cannot hurt them, how to run several at once without losing track, and how to give an agent its own user. Org-level Omarchy exists on two fronts that have nothing to do with agents yet: upstream's unattended installs and Fleet's MDM support, plus one home fleet with agents as participants. Multi-user is the standing gap upstream has promised for 4.1.

## What this means for the plan

Judgment, not measurement. Keepalive's record and receipt have no neighbour; that is the thing to keep saying plainly. Lanes have one close neighbour, Maestro, and several homegrown versions (qj-orch, grbrum's planner and executors, agentic-dev-setup); what none of them has is the completion path, the merge with a visible conflict, and the receipt per lane, so slice 2's report should compare against Maestro by name. The remote case is live now: Herdr on a VPS, Omarchy in QEMU as an agent workstation, per-VM identities in #7956; slice 3's second-host path (an answer path for a blocked agent from another machine, Herdr `--remote`) is the next thing people would actually use, ahead of the second OS account, which waits on 4.1. Axon is the one announced product that could sit above the desktop as a fleet manager; worth a look before slice 4 decides what "structured fan-out" means. And the recurring "run it somewhere safe" question suggests a section in the listing README on running Keepalive inside an Omarchy VM, since that is the sandbox DHH points people to.

## What this cannot claim

Discord's search is by keyword and returns the newest matches first; a conversation that used other words was missed, and long threads were read only where a hit led into them. GitHub's search pages could not be fetched, so the Discussions and Issues coverage came from web search plus opened pages; a discussion that search engines have not indexed was missed. `plugins.omarchy.org` is rendered by JavaScript and its catalogue was cut at 80k characters, so the plugin list is what OmaPicks, the marketplace issues, and opened repositories showed. Install counts are OmaPicks figures. Nothing here was verified by running the other tools.
